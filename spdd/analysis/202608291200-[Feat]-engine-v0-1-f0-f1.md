## 2. Decisions locked with the requester before generation

1. **Solid / ADR-0011 path**, _not_ the "verbatim PRD-002" path of `IMPLEMENTACAO-DETALHADA-V0-1.md` §2.1-2.2.
   `core/engine` stays a pure abstraction: no `rhai` dependency, an own `EngineType` marker trait in place of
   `rhai::CustomType`, a single `EngineError` enum, object-safe required methods with PRD-002 generics kept as provided
   sugar.
2. **Scope of this increment**: F0 + F1 only. F2 (`core/runtime/rhai`) and the `alloy` binary are the next increment.
3. **SPDD**: this analysis + a REASONS canvas are written _alongside_ the code (not gated on `/spdd-generate`),
   satisfying `ADR-0007` / N-05.

## 3. Contradictions resolved in this increment

| Contradiction                                                                                                       | Resolution                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `PRD-002:42` `eval<T>` takes a fresh `&str`, ignoring `compile()`; hot-reload (F11) needs `Arc<AST>`                | `eval_value` / `eval_compiled_value` are the object-safe required core; `eval<T>` / `eval_compiled<T>` are provided sugar. `CompiledScript: Send + Sync + 'static`. |
| `PRD-002:37,46` give each trait a `type Error`; `ADR-0011 item 4` mandates one enum per port                        | Associated `type Error` dropped; every signature returns `EngineError`.                                                                                             |
| `PRD-002:51` references `EngineFunction<Args, Ret>` but never defines it                                            | Defined in `application/function.rs`; blanket impls for closure arity 0-4.                                                                                          |
| `PRD-003:76-77` capability check on _every_ binding vs. `<10µs` hook budget (`PRD-001:96`)                          | v0.1 stores the `CapabilitySet` and exposes `CapabilitySet::require`; per-binding enforcement is F6/v0.2.                                                           |
| `.gitignore:4` ignores `Cargo.lock` (library convention) — wrong for an application about to pull `rhai`            | Removed from `.gitignore`; lockfile versioned now.                                                                                                                  |

## 4. Existing code touched

- 11 crates were `cargo new` stubs (`pub fn add`). This increment replaces `core/engine/src/lib.rs` with the real facade
  and adds `#![forbid(unsafe_code)]` to the other nine `core/*` + `devtools` + `extension` stubs (stubs otherwise left
  for their own increments).
- No crate depended on `engine` except `core/runtime/rhai` (path dep, unchanged).
