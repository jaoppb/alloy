# Triagem de despacho — o que é leve o bastante para outra IA conferir só depois

Nem toda tarefa das sete fases restantes pede o mesmo nível de acompanhamento. Esta triagem separa o que é **mecânico**
(segue um molde já existente, tem verificação automática que prova certo/errado sozinha, cabe num prompt parametrizado)
do que **exige julgamento** (interpretação de spec, decisão de design, uma invariante que nenhum teste cobre sozinho). O
critério não é "quanto código", é **quanto a correção depende de quem escreveu entender o resto do sistema** — uma
tarefa 🟢 pode ir para uma IA mais barata/rápida (ou para outra sessão sem contexto nenhum da campanha) e ser conferida
só pelo `Definition of Done` do arquivo da fase; uma tarefa 🔴 precisa de alguém acompanhando enquanto escreve, porque o
`just gate` verde não prova que a decisão de design certa foi tomada.

## Como usar esta triagem

1. **Antes de despachar uma tarefa 🟢**, é seguro passar só o arquivo de fase correspondente (ou o trecho específico,
   para as sub-tarefas de B4) para uma sessão nova, mesmo com um modelo mais leve — o `Definition of Done` de cada
   arquivo já é a verificação inteira.
2. **Para 🟡**, despache normalmente, mas reserve um passo de revisão humana (ou de uma sessão mais cara) focado
   exatamente na coluna "o que confere depois é suficiente" — não é preciso reler tudo, só o ponto apontado.
3. **Para 🔴**, não despache como tarefa isolada de "escreva e me avise quando `just gate` estiver verde". Acompanhe a
   decisão de design enquanto ela é tomada, ou pelo menos reserve uma revisão de código dedicada antes do commit — essas
   duas tarefas são onde um `just gate` verde e uma implementação errada podem coexistir.

Esta triagem cobre tarefas de **implementação**. As sub-tarefas de escrita de teste dentro de cada fase (B5 item 5, X
"alvos de fuzz", I2/I4 "teste golden") **não** aparecem separadas porque já herdam o nível da tarefa de implementação
que testam — um teste para uma tarefa 🟢 é 🟢, porque a prova de corretude do teste é a mesma prova de corretude da
implementação (o golden bate ou não bate).
